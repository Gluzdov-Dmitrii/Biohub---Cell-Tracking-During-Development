# EXP219: полезная проверка OOF-фронтира на LB

Кандидат: `dmitriigluzdov/biohub-exp219-frontier90-public`, версия1, PRIVATE_ROBUST slot3. Пользователь разрешил одну полезную отправку 16 сентября. Текущее состояние и ref после отправки: `exp219_submission_progress_20260916.json`, полный API — `exp219_submission_full_api_20260916.json`.

Выбраны веса лучшего подтверждённого локального варианта: EXP214 gapfix90, pooled OOF175 **0.7427291486246141**. Primary обучен90эпох, secondary60; веса выбраны по исходной валидации. EXP217 дал регрессию, EXP218 не дал улучшения. Подтверждённый публичный рекорд аккаунта на момент выбора — **0.947**, ref56243810; цель данной отправки — измерить перенос локального решения, а не повторить этот результат.

Изменения production: публичный граф с исправлением сериализации координат вне изображения; один заранее выбранный source на ролик вместо двойного неизвестного-fold-инференса. Для известных префиксов сохранена противоположная чистая модель. Для неизвестных используется source6bba, обученный на большей исходной группе. Ролики распределяются между двумя GPU по размеру изображения. Это отдельное непроверенное на неизвестных эмбрионах правило маршрутизации: OOF0.742729 нельзя присвоить ему автоматически.

Приватный model dataset: `dmitriigluzdov/biohub-exp219-frontier90-models`. Manifest SHA `1695d69c70567b398714aabfa99d14691904dec83f7d4ff51fc1675aecc92d86`. Проверены32файла. Никаких сохранённых тестовых предсказаний в dataset. Точный удалённый source SHA `dcc140873e155862629f6294f5abdb745cb5d36f11b7b76c861e111134d7ba0a`; Kaggle нормализовал CRLF в LF, локальный контрольный файл приведён к тем же байтам без изменения текста/версии. Удалённые isPrivate=true, enableInternet=false, version1 подтверждены API.

До POST обязательны: COMPLETE чистого запуска, совпадение source/version, полный перечень выходных файлов с единственным корневым submission.csv, загрузка CSV/runtime/fold receipts, SHA, типы, конечные значения, точное равенство runtime dataset IDs, целостность графа. 17 тестов защищённого helper и аудита прошли. Отправка только через `scripts/submit_code_file_once.py`, без повторного POST при неоднозначном ответе; затем чтение полного API с error/status/score/bytes/ref/URL/quota. Нулевые bytes и пустой score допустимы при PENDING, но не при COMPLETE.

Предыдущие неудачи EXP214v2: public — incorrect format без раскрытой точной причины, local — превышение runtime. Исправление координат и сокращение двойного инференса устраняют известные риски, но успешный открытый прогон не гарантирует успех скрытого.
