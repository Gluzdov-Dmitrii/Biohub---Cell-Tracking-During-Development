# EXP225: сильная воспроизводимая основа для LB

Рабочий notebook: `kaggle_notebooks/exp225_p26_research/biohub-exp225-p26-research.ipynb`.
Kaggle: https://www.kaggle.com/code/dmitriigluzdov/biohub-exp225-p26-research-and-frozen-inference .

## Почему выбран этот вариант

За час разумная цель — подготовить и проверить наиболее сильную уже подтверждённую систему, сохранив возможность дальнейших экспериментов. P26 дал аккаунту 0.947 на public LB, ref 56243810. Чистые fold-модели EXP219 дали 0.922, ref 56277173. Оба значения заново проверены полным API. Horaz selected показал 0.7949879415 на нашей локальной когорте из 175 роликов против 0.7427291486 у EXP214, но fixed-last Horaz даёт 0.7386985046. Поэтому заменять production P26 на Horaz или смешивать их без проверки сейчас не обосновано.

0.947 — результат родителя; это ещё не score EXP225. Чистый прогон EXP225 уже побайтово воспроизвёл публичный CSV родителя. Точное приватное качество неизвестно: публичные веса обучены на всех train-данных, а историческая настройка postprocess выбрана по train-proxy. Ни наш CV, ни Horaz CV не являются OOF-оценкой этих конкретных production-весов.

## Что находится в ноутбуке

35 ячеек кода и 36 поясняющих Markdown-ячеек. В начале — назначение системы, ограничения доказательств, таблица основных параметров, требования к запуску и ссылки на авторов. Затем: конфигурация; установка offline-зависимостей; проверка SHA кода и весов; нейросетевой инференс на двух GPU; физическое связывание и восстановление графа; финальная проверка. В конце — порядок дальнейших экспериментов.

Цепочка вычисления: реальные runtime test Zarr -> два TemporalUNet/transformer seed -> TTA и объединение оценок связи прямого/обратного времени -> ILP -> motion relink/gaprepair/ограниченные деления -> проверка DeepCenter -> фильтрация коротких компонентов -> CSV. Нет маршрутизации по известным embryo ID и нет чтения сохранённых тестовых предсказаний.

## Изменения относительно P26

1. Исторический прогон выбрал только `MOTION_RELINK_TIGHT_UM=5.5`. Эта настройка зафиксирована до вычислений; повторный train-validator/sweep удалён. Историческое смещение от отбора при этом остаётся явно указанным.
2. Найден и воспроизведён пограничный случай: сглаживание валидного трека может дать 29.5333 на оси длины 30, а округление превращает координату в 30. Только при записи CSV XYZ ограничиваются фактическими границами ролика runtime test. Исходные дробные координаты при построении графа, время, IDs и рёбра сохраняются.
3. Исправлены унаследованные ложные диагностические сведения о параметрах и происхождении. Отчёт теперь сохраняет фактически использованную конфигурацию и честно указывает историю train-proxy.
4. Финальный аудит проверяет единственный корневой CSV, схему, конечные целые значения, соответствие динамическим dataset ID и размерам, отсутствие висячих и повторных рёбер, соседние кадры, indegree<=1, outdegree<=2 и SHA.

Все функции исходного графового блока, кроме `write_test_submission`, совпадают по AST. Нейросетевой инференс и подготовка моделей сохранены точно. Регрессия границ воспроизведена на трёх осях; отдельно проверены 18 случаев фактических выражений writer. 41 тест защит отправки и аудита прошёл.

## Воспроизведение и развитие

Ноутбук запускается на Kaggle T4 ×2 с Internet OFF и тремя указанными в metadata наборами моделей. Модели и код зависимостей фиксируются SHA. Локальный builder: `python scripts/build_exp225_notebook.py --append-audit scripts/exp225_output_audit.py`. Исходная нормализованная версия Kaggle отдельно сохранена в `work/exp225_20260922/remote_source.ipynb`.

Для следующей качественной итерации сначала нужен исследовательский вариант на чистых folds с выбор checkpoint только на исходном эмбрионе. Затем — одна гипотеза по детекциям/association, полный парный набор предсказаний и официальный scorer. Сильный ближайший исследовательский кандидат — воспроизведённый Horaz, но его выбор checkpoint нужно отделить от окончательной оценки. Автоматический выбор алгоритма по известному embryo ID или добавление новых публично подобранных порогов не решает проблему валидации переноса на приватные данные.

Для ускорения будущего запуска можно отдельно исследовать копирование только нужного secondary checkpoint и config: в исходном логе этап от SHA primary и DeepCenter до SHA secondary занимает 433 секунды. Это измерение исходного запуска, а не уже реализованная оптимизация; текущая версия сохраняет проверенный loader.
