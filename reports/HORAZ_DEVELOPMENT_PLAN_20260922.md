**Приоритет 24 сентября, после уточнения пользователя.** Главная цель — как можно скорее проверить на LB новый сильнейший кандидат с подтверждённой локальной OOF-основой. У EXP209 такой зафиксированный OOF есть, но его точный production-вариант уже проверен на LB (EXP212, 0.718); повтор бесполезен. EXP219/EXP233 уже дал 0.922, но не проверяет unseen-embryo router. Для Horaz ближайшая новая информация — закончить заранее запущенный EXP228 (chunk05 стартовал) и отдельно построить отбор/checkpoint/decoder только на source-эмбрионе. EXP228 сам по себе не проходит честный OOF из-за исторического выбора selected20 по target. Не отправлять эту ветку как «проверенную» лишь на основании высокого development-score. Следующий новый LB POST только после совпадения точной production-схемы с локальным протоколом и всех чистых Kaggle-гейтов.

**Уточнение 24 сентября.** Пользователь подтвердил строгий смысл второго варианта: Horaz-основа с честной локальной OOF-проверкой именно той модели и того правила инференса, которые пойдут на скрытый тест. Отправленный EXP233/EXP219 (исторический LB 0.922) этому условию не соответствует: это наша другая модель, а её маршрутизатор для неизвестного эмбриона не проверен OOF. EXP233 остаётся только диагностикой исполнения. Текущий Horaz selected50/20 (0.794988/175) также не проходит строгий критерий из-за выбора эпох по внешнему эмбриону; fixed-last50 (0.738699/175) устраняет эту конкретную утечку, но не даёт независимой оценки всей исторически настроенной схемы. До нового PRIVATE_ROBUST POST нужно зафиксировать выбор чекпоинта и decoder только по source-данным, выполнить оба направления без доступа к target-меткам до фиксации всех предсказаний, проверить отдельно политику для неизвестных эмбрионов и затем провести чистый Kaggle notebook-run с обязательным аудитом. При двух уже использованных в разработке эмбрионах это будет усиленная проверка переноса, не абсолютная гарантия private.

Решение пользователя от 22 сентября: сохранить две разные основы. P26/EXP225 — вариант с сильным public LB и неизвестным качеством на новых эмбрионах. Horaz — направление локального развития с явным разделением обучения и проверки. Второй вариант пока нельзя называть проверенным на private: такой статус должен опираться на результаты следующих этапов.

## Этапы и условия перехода

**Запущено параллельно 23 сентября local.** По уточнению пользователя обучение с нуля продолжается, пока не мешает другим. Три независимые гипотезы: EXP227 — новый source-only checkpoint; EXP228 — фиксированное усреднение двух готовых snapshots в одном fold; EXP229 — геометрическое связывание неизменных детекций Horaz. A100 / Quadro / CPU соответственно. Текущие процессы, ограничения и порядок проверки записаны в `reports/HORAZ_PARALLEL_20260923.md`; это актуальный порядок исполнения. Fine-tuning остаётся следующим небольшим опытом после освобождения ресурсов. Для новых веток пока нет итогового качества.

**Уточнение приоритетов после вопроса пользователя о готовых весах (23 сентября local).** Обучение с нуля нужно для новой source-validation, которую начальная модель не видела, но оно не является обязательным условием полезной локальной разработки. Приоритет полного переобучения был выбран слишком рано. Уже запущенный EXP227 ограничивается текущими пятью эпохами как контроль обучения; переход к следующим блокам по прежней очереди откладывается.

Ближайший основной маршрут: (а) один заранее зафиксированный ансамбль готовых Horaz snapshots в пределах соответствующего fold; (б) короткое дообучение готовых selected-весов на их source-эмбрионе с новым optimizer и заранее фиксированными LR/числом шагов; (в) при доказанной совместимости — ансамбль Horaz с чистыми fold-моделями EXP214. Исторический selected baseline остаётся неизменным. Новые source-only fine-tuning и ансамбль сохраняют отсутствие обучения на внешнем эмбрионе, но не устраняют исторический выбор исходных epochs по outer-fold. Новую inner-validation из source-роликов нельзя считать ранее невиданной для этих pretrained-весов.

Проверка фактических tensor state выполнена на CPU: fold0 selected50 и last50 имеют одинаковые **136/136 tensors**, ансамблировать их вместе бессмысленно. Fold1 selected20 и last50 отличаются по всем **136 tensors**; это доступная пара для первого snapshot-ансамбля. Штатный Horaz ensemble усредняет detection logits и edge probabilities до decoder. Первое сравнение — фиксированное равное усреднение этой пары с неизменным decoder, без sweep весов; на fold0 используется одна копия одинаковой модели. Это диагностический development-кандидат, не заранее обещанное улучшение. Его inference ещё не запускался.

У selected-файлов нет optimizer/RNG; warm-start с новым optimizer доступен. У fixed-last есть optimizer и RNG, но точное resume дополнительно требует совместимого источника, конфигурации и порядка данных. Для новых test-эмбрионов можно объединять обе fold-модели. На локальном heldout-эмбрионе нельзя включать модель другого fold, обученную на нём. P26 all-train не входит в локальный ансамбль, претендующий на heldout-оценку. Проверка: `work/horaz_development_20260922/pretrained_diversity_audit.json`.

Ниже сохранён исходный долгосрочный протокол строгого source-only обучения; он остаётся отдельным контрольным направлением, а не обязательным предшественником ансамблей и fine-tuning.

1. **EXP226 — изоляция данных и рабочее обучение.** Зафиксировать исходный код Horaz и отдельный адаптер обучения без вызова авторского outer-fold CV. Детерминированно разбить source44 на train/inner-validation. Начать с нуля: опубликованные веса видели source-validation и не годятся как начальная точка такой проверки. Первый пилот: 4 source-train ролика, 2 отдельных source-validation ролика, 2 эпохи по 8 minibatch, исходные архитектура/AdamW/loss/augmentation, один A100, максимум 2 часа. Проверить конечные loss/градиенты, изменение весов, сохранение/загрузку checkpoint, отсутствие доступа к target и фактические время/VRAM. Пилот не выбирает модель по качеству и не создаёт OOF-score.
2. **Полное source-only обучение и выбор эпохи.** После оценки времени пилота подготовить обе стороны одинакового протокола: внешние эмбрионы 44b6/6bba, внутри обучающего эмбриона отдельные ролики для выбора checkpoint. Обучение с нуля; исходные 50 эпох, seed и параметры фиксируются до запуска. На эпохах 10/20/30/40/50 получить графы только inner-validation, выбрать максимальный официальный score, при равенстве — раннюю эпоху. Не использовать целевой эмбрион для ранней остановки, нормализации, выбора эпохи или decoder. Полный бюджет и размер последовательных вычислительных блоков зафиксировать после пилота. Возобновление из собственного checkpoint — только с точным совпадением конфигурации, RNG и optimizer.
3. **Один зафиксированный парный внешний замер.** До чтения целевых labels сохранить SHA выбранных моделей, decoder, manifest175 и scorer. На каждом эмбрионе работает только модель, обученная на другом. Все 175 предсказаний и графовые проверки должны завершиться до scorer. Отчёт включает обе стороны, агрегат, парные ошибки, node recall, деления; хужее направление не скрывается. Первый критерий перехода: превзойти frozen fixed-last по обеим сторонам и по агрегату; сравнение с EXP214 и selected50/20 остаётся обязательным. Если критерий не пройден, сохранить отрицательный результат, не перебирать эпохи по target.
4. **Доработка графа по одному компоненту.** На зафиксированных предсказаниях проверить одну мотивированную ошибками гипотезу: разрывы треков, ложные связи или деления. Настройка только на source-validation; полный парный scorer после фиксации. Из P26 можно переносить отдельный геометрический алгоритм с самостоятельной проверкой. Его all-train веса не включаются в локальный evaluator Horaz.
5. **Второй production notebook.** После достаточных локальных доказательств зафиксировать правило обучения/refit и объединения моделей для новых test-данных. Подготовить понятный notebook с runtime test inference, offline-зависимостями, SHA и аудитом графа. Провести чистый Kaggle-run и guarded submission в PRIVATE_ROBUST. Финальный портфель содержит P26 и Horaz; резервный EXP214 сохраняется до появления более убедительного результата.

## Ограничения доказательств

Есть только два эмбриона, оба уже использовались при разработке. Даже аккуратный новый протокол остаётся development-оценкой, а не независимым финальным тестом. Source-validation по роликам одного эмбриона может содержать пространственно/временно связанные фрагменты. В проверенных Zarr metadata нет acquisition/group ID для более строгой группировки; текущий split не выдаётся за независимые биологические образцы. Перед полным обучением дополнительно проверить доступные исходные метаданные и при наличии групп закрепить правило по группам до обучения.

Выбор по source-validation loss допустим как явно объявленный proxy, но не равен официальному graph-score и не будет незаметной заменой основного правила. Рекомендация внешнего reviewer полностью запрещать loss как критерий чрезмерна; принимаем предупреждение о слабом переносе ранжирования эпох между эмбрионами. Два seed полезны позже для устойчивости, но не нужны, чтобы проверить первый запуск.
